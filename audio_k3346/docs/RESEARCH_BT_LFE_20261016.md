## 1. Bluetooth / USB / SD -> mm-renderer -> MPL1: where a hook can sit
- Car [log]: `libnvaudio.so: mm-renderer (pid ...) nvaudio_pcm_open: path:MPL1`, mm-renderer opened MPL1 at 44100/16 stereo; BT A2DP arrives through mm-renderer's mdev streamer (`mdev_streamer:NextBuffer`).
- [static] `/etc/mm/mm-renderer.conf` loads routing plugin `mmr-nvidia-routing.so` (writer_prio 17). It NEEDs `libmmro-nvidia.so.1`, `libnvaudio.so`, `libnvmedia*.so`; audio goes through NVIDIA media classes (`INvmStreamAudio`, `INvmFileAudio`, `INvAudio::GetNvAudio`, libs not in app.img, probably in the MMX IFS). `libnvaudio.so` exports only 15 C symbols (`nvaudio_pcm_open/close/info/read/write`, `nvaudio_set_pcm_info`, ...).
- [inf] Therefore the SAME seam as our CarPlay stock bridge (`prototype/nvaudio_stock_bridge.h`, LD_PRELOAD of `nvaudio_*` into dio_manager, default device "MPL5", claims only 48k/S16/2ch) can serve mm-renderer: device "MPL1", claim 44.1k/S16/2ch (SCENE runs at 48k: use the existing 44.1k resampler, PASS in run 153224, or a 44.1k SCENE config). Passthrough for everything else stays.
- Open, in order: (a) how mm-renderer is launched and whether LD_PRELOAD can be injected (read on car: `pidin -p <pid> env`, launcher script; mm-renderer runs from `/mnt/app/armle/usr/sbin`); (b) the exact `nvaudio_set_pcm_info` struct mm-renderer passes (rate/ch/bits, like `c[0..2]` in the bridge); (c) mm-renderer pause/seek/track change -> close/reopen behaviour (gap-free gate); (d) CPU: SCENE + mm-renderer decode on Tegra3.
- Emulator test possible NOW (no car): `nvaudio_play` is itself a plain libnvaudio client; run it in the QNX guest with a 44.1k stereo WAV on MPL1 and the bridge variant (`SPA_NV_STOCK_DEVICE="MPL1"`, 44.1k claim) via LD_PRELOAD, capture TDM like runs 162833/163604. This proves the claim/upmix/sink path for an mm-renderer-like client, not mm-renderer itself.

## 2. Why discrete ch4 (LFE) was silent
- Facts: [ear] ch1 FL, ch2 FR, ch3 C, ch5 RL, ch6 RR correct; ch4 silent at 60/90 Hz and 40-200 Hz sweep; front sweep drives the sub. [static] owner's DSP: sub output LPF2 120, HPF2 50 x2, peak 67 Hz +3, gain +100 (passes 60-90 Hz). [static] AudioTable `amplifier id 122 settings AU_6CH`, default amplifier attrs `subwoofer="1" subwooferActivity="1"`; AU_6CH SUB levels 0, SUBACTIVITY on/off.
- [static, reference doc] RCC MainMix tables: source map rows `{0,0,1,2,3,4,5}`, channel maps (K3346 `0x8760ac88/ad18/ada8`), "C/LFE output gains [4]=[5]=0.5" in the reference; semantics not decoded, so the LFE input->sub output coefficient on this car is unknown.
- [web] SEAT forum (unverified): in PR 9VD the sub is on Quadlock pins 9/13 and the centre on 10/14 (the same pins carry front woofers in the 8-speaker mode); internal amp is 6-channel with 2/4/5.1 modes (Strelets). No datasheet found for the RCC amp/DSP (DSP is TI Jacinto-5 class C674x, `/dev/dspipc/dra6xx`).
- Hypotheses (cheapest test first): H1 the TDM frame has 8 slots and LFE sits on slot 7/8 or a different index (we only ever drove 6 slots); H2 MainMix maps LFE input to the sub with ~0 gain in this signal flow (sub = bass management of the fronts only); H3 the sub output is gated by the AM SUB level/activity for the media source.
- Decisive car test (one visit, writes only WAVs to /tmp): 8-channel 48k WAVs, one-hot per slot 1..8, 70 Hz then 1 kHz tones (owner listens for which speaker/sub, told in advance); plus 40-200 Hz sweeps on C only and RL+RR only (does the amp bass-manage centre/rears into the sub?). If no slot drives the sub: H2/H3; then fold LFE into L/R in the hook (bass management already sends it to the sub).

## 6. Web research round 2 (2026-10-16): how the sub/centre are fed on MIB2/MHI2 [web = forum, unverified]
Sources: mqb-blog.com/en/2022/02/21/sound-dataset/ (NumberOneBot, repo `NumberOneBot/mqb-mib2-sound-datasets`, 010 templates), M.I.B. issue #99 / discussion #151 (Mr-MIBonk), audi-sport.net thread 436166 (A3 8V, Oli250/Allan_84). audiworld.com returned 403. Pages were partly truncated by the fetcher; summaries inside them are model-generated.
- Amp: 6 output channels in dataset order RR, FR, FL, RL, SUB, CENTER; modes 2/4/6 (stereo/quadro/5.1) [web, matches our owner doc].
- NOTHING found documents how the DSP derives the sub or centre from stereo/5.1 input, nor any dedicated LFE input mapping. The MQB blog has no routing/mix matrix and no 'signalflow' field text (only images).
- Only sources of sub-related bytes: 0x3000 byte0 Signalflow (0x30 = 6ch 5.1; the owner's doc: 0x31 = 6/4/2 compatible, stock here 0x20); 0x3000 byte31 'sub max gain' (A3 report: 00 -> 5A made the sub dial work; this car: stock 0x5A, owner v16 0x78 [log]); 0x3B00 bytes 24-26 knob range (F7 00 09; owner's attempt broke the MMI controls, K3346 MU1438 is explicitly listed as NOT working for the M.I.B. knob feature [web]).
- brucemiranda (M.I.B. discussion, May 2026): the knob feature does not reconfigure the amp, a separate feature enables all 6 channels; a summary-only claim says a user (VW MHI2) got sub + knob but 5.1 media was still DOWNMIXED, source possibly downmixing. Unverified.
- Reports that the sub knob position resets after power cycle/source change on some units.
- Conclusion: no public method to address the sub/LFE input exists; the community only shapes the SUB OUTPUT (gain, filters, delay) through 0x3000. Consistent with our ear result (sub fed by DSP bass management).
- New testable lead (H4, not tested, dataset write = owner decision): Signalflow 0x31 ('compatible') may make the DSP adapt the input channel count itself; 0x30 (pure 6ch) might interpret a 6-ch input differently (LFE on ch4?). Reversible via CarScanner with the 692A/4454 backups, but the owner's earlier 0x3B00 edit showed plausibility validation can disable all MMI controls: only with a backup and an explicit owner decision.

### 6b. GitHub round 3 (2026-10-17)
- NumberOneBot/mqb-mib-sound-datasets 010 templates (0x3000 v0.6, 0x3B00 v0.1): no routing/LFE/downmix field at all. Byte0 Signalflow enum: 0x10 2ch, 0x20 4ch, 0x21 4/2 compat, 0x25 5.0, 0x30 6ch 5.1, 0x31 6ch 5.1 /4/2 compat, 0x32 4.2, 0x33 4.2 compat, 0x34 4.0 bi-amp, 0x35 bi-amp compat.
